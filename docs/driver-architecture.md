# Minex 驱动架构（Driver Architecture）

> 2026-08-12 定稿。改名：插件 → **驱动（Driver）**。语义：驱动 = 功能模块，类比设备驱动——**没有驱动，软件没有任何功能**。软件 = 空壳 + 一组驱动。

---

## 一、分层

```
内核   机制：注册表 / 事件 / 存储 / 生命周期（领域无关）
外壳   顶栏（驱动选择器 / 命令面板 / 深浅切换 / 设置）+ 工作区挂载点 + 主设置页
驱动   工作区提供者：决定顶栏之下整个区域（左/右栏有无、内容、主体）+ 可启用/禁用
```

## 二、驱动

- **改名**：Plugin → Driver（DriverContext / DriverManifest / DriverModule / DriverState / kernel.drivers / loadDriversFromDir）。
- **启用/禁用 = 激活/停用**（已实现：discovered→activated→deactivated/failed，容错/reload 完整）。
- **工作区贡献**：驱动贡献 `driver/workspace` 类型，声明自己的工作区布局（顶栏之下）。
- 类全部保留，驱动可选择是否实例化（激活）。

## 三、外壳

- **顶栏（固定）**：
  - 左：驱动选择器（下拉、滚动式、支持搜索；选中后按钮旁显示驱动图标+名）
  - 中：命令面板（`/` 指令分区：主设置 / 某驱动设置 / 打开文件…；对齐 VS Code 习惯）
  - 右：深/浅色一键切换 + 设置入口（进主设置页）
- **顶栏之下 = 当前驱动的工作区**（驱动决定布局）。
- **主设置页**：全屏大界面（非浮窗、无顶栏）；左栏设置导航（文件夹式可展开折叠）；主体为详细设置。

## 四、布局引擎

侧栏面板系统（底层组件，驱动声明自己的工作区用它）：
```
Panel { position: "left"|"right", visible: boolean, collapsible: true, tree: 文件夹条目 }
```
- 左/右栏：可折叠（所有）、可切换位置（左↔右 = 改 position）、可隐藏、支持文件夹视图。

## 五、主题系统

```
主题（Theme）= 一套 CSS 值（颜色/字体），存成文件（主题文件夹）。
系统自带：default-dark.css / default-light.css。

顶栏切换语义：当前在深色 → 点击 → 切到浅色模式的默认主题；反之亦然。
  （A 模式 ↔ B 模式，各用各的默认主题）

外观驱动：提供更多主题（配置/下载，存主题文件夹）；指定「哪个主题是默认深/浅色」。
  无外观驱动时，默认 = 系统自带。
```

「深/浅模式」= 二元开关；「主题」= 实际 CSS；映射「模式 → 默认主题」由外观驱动可配置。

## 六、外观驱动（第一个驱动）

- 配置：背景颜色、主题色、系统中文字体、系统英文字体、内容中文字体、内容英文字体、代码字体。
- 两种模式（选项卡切换）：条目式管理（常见设置表单）+ CSS 代码编辑。

## 七、构建顺序

```
① 外壳重设计：顶栏（选择器/命令面板/深浅切换/设置）+ 工作区挂载 + 侧栏面板系统
② 驱动机制：driver/workspace 贡献 + 启用/禁用管理
③ 主题系统：主题文件夹 + 默认深浅色 + 切换 + CSS 注入
④ 外观驱动：主题管理 UI + 条目式设置 + CSS 代码编辑
```

## 八、驱动图标

- **图标 = 驱动内图片文件**（如 `assets/icon.svg`），不是 emoji。
- `DriverManifest.icon?: string` 存图标引用：
  - 文件加载场景（CLI/Electron）：相对路径（相对驱动目录）；
  - Vite 打包场景（Web）：驱动源码经 Vite 解析为资产 URL，UI 用 `<img>` 渲染。
- UI 统一用 `DriverIcon` 组件：图片优先，emoji/文本兜底。

## 九、驱动间交叉关系（数据流）

驱动之间会有交叉：专门驱动依赖**基础驱动**，向基础驱动提交数据；基础驱动聚合所有驱动设置与数据，统一上交给内核；内核做功能调度或上交给 UI 渲染层。

```
专门驱动 A ──依赖──► 基础驱动 B（提交数据/设置）
专门驱动 C ──依赖──► 基础驱动 B（提交数据/设置）
                              │ 聚合
                              ▼
                           内核（注册表/事件/存储）
                              │ 调度 / 上交给 UI
                              ▼
                           UI 渲染层
```

实现机制（内核已支持，无需新原语）：
- **依赖**：`manifest.dependencies`（激活顺序保证，A 激活前 B 先激活）。
- **贡献**：A/C 通过注册表向 B 提交数据（`contributes` 类型由 B 定义）。
- **事件**：数据变化经事件总线通知。
- B 聚合后写入存储/注册表，内核消费或交 UI。

## 十、UI 组件配置驱动化

外壳的 UI 配件（深浅切换按钮图标、折叠图标、文件夹视图图标、命令面板图标等）**不应硬编码在外壳**——应由驱动/主题提供。v1 先保留外壳默认图标，外观驱动落地时把图标纳入其提供的资源（与颜色/字体同级）。
